# ShowNow: Fine-Grained Speculative Streaming for Responsive World Models

## Abstract 中文翻译

交互式世界模型必须在持续生成视频的同时，及时响应用户动作。仅有实时吞吐率并不能解决输入延迟：粗粒度生成会阻塞并延迟动作更新，而在输入之后才开始生成又会增加响应路径上的工作量。我们提出 ShowNow，一种细粒度推测式流式框架，利用播放期间可用的计算资源，在输入到来之前准备动作条件化的未来。单潜变量提交支持频繁决策，可配置的准备机制覆盖一至八种动作。我们构建了匹配的多未来数据集，用于从共同状态训练不同的后续轨迹；共享历史的树式执行与融合提交使这些未来的准备更加高效。在单张 H100 上，我们的 5B 模型在准备八个未来的情况下，能够以 16 fps 生成 480p 视频。在 ViZDoom 中，相较于原生阻塞式 SolarWM-FT 部署，完整的 ShowNow 部署将输入到显示的中位延迟从 620 ms 降至 208 ms。匹配策略实验将重启空显示帧比例从 1.56% 降至 0.09%（降低 94%），并提高了动作变化的按时响应率。这些结果表明，细粒度提交与提前准备具有互补作用，同时也存在经过测量的视觉保真度和长时一致性权衡。ShowNow 将播放期间的计算转化为响应迅速的视觉交互。项目地址：https://github.com/showlab/ShowNow。

## 全文总结

本文提出 ShowNow，用于降低动作条件视频世界模型的交互延迟。它在视频播放期间提前生成一至八种可能动作对应的未来，并在用户输入到达时选择匹配分支继续生成；单潜变量提交缩短了动作决策间隔，共享历史树式注意力、缓存复用和融合提交则降低了多分支推理成本。基于 SolarWM/Wan2.2 5B、匹配多未来 ViZDoom 数据集、AnyFlow 蒸馏和 Self-Forcing 训练，系统在单张 H100 上以 480p、16 fps 准备八个未来。实验显示，完整部署的输入到显示中位延迟为 208 ms，相比原生 SolarWM-FT 的 620 ms 明显降低；八未来策略还将重启空帧比例从 1.56% 降至 0.09%，并提升接近显示截止时间时的动作响应率。研究同时发现，细粒度自回归和更长历史会带来视觉质量及长时一致性下降，体现出响应速度、计算开销、保真度和连续性之间的权衡。

## 核心贡献

1. 提出细粒度推测式流式框架 ShowNow，将播放期间的空闲计算用于输入到达前的动作未来准备，并统一单未来与多未来策略，提供可调节的计算量—响应速度权衡。 2. 构建并发布匹配的多未来数据集：从相同 ViZDoom 状态生成八种动作条件化后续轨迹，覆盖持续动作和动作切换，并配套多未来训练与因果蒸馏流程。 3. 提出共享历史的分支树执行、分区注意力、历史缓存复用和融合提交，使多未来生成高效运行。八候选生成相较于独立批处理将生成时间降低约 10%，峰值显存降低 48%。 4. 在单张 H100 上实现 5B 模型 480p、16 fps 的八未来实时流式生成，并通过连续流、受控切换、播放调度和 32 fps 压力测试验证其延迟、连续性与截止时间响应收益。

## 与课题的关系

与视频生成和视频扩散直接相关：模型基于 Wan2.2/SolarWM 视频生成骨干，并结合流匹配、AnyFlow 因果蒸馏和 Self-Forcing，将多步生成压缩为实时因果生成。与动作条件视觉世界模型和闭环模拟直接相关：系统从 ViZDoom 共享模拟器状态生成不同动作的视觉未来，用户动作选择分支后，该分支成为下一轮生成的共同历史，形成持续的感知—动作—视频反馈闭环。与自回归、因果、流式和长视频生成相关：单潜变量、块因果注意力、历史窗口缓存和反复的准备—选择—提交循环支持连续流式生成，并测试了一分钟场景。与实时生成、蒸馏、稀疏注意力和缓存复用相关：AnyFlow 与 Self-Forcing 用于降低采样步数；分支树注意力隔离候选未来并共享历史；FastTree 缓存最近提交潜变量的键值；融合提交和 CUDA 图进一步缩短响应路径。其核心价值是把生成工作前移到播放阶段，从而降低输入到显示的延迟，尤其适合动作变化接近显示截止时间的交互场景。

## 局限 / 待核实

论文明确显示，ShowNow 的细粒度自回归存在视觉质量和长时一致性权衡：其 LPIPS 和部分长视频指标劣于教师模型、普通推理或 SolarWM-FT，部署融合和更长自回归历史也会降低 rollout 质量。ShowNow 的整体性能依赖 GPU 余量、播放队列深度、输入时机、动作覆盖率和调度策略；未覆盖的动作仍需在输入后重新生成。多未来准备增加计算负担，八未来虽通过共享历史降低了成本，但仍使用约 80% GPU 忙碌时间。实验主要基于 ViZDoom 和有限动作集合，论文未证明其对更复杂开放世界、更多动作或真实机器人环境的普适性。32 fps 结果是对以 16 fps 内容进行 2 倍播放的压力测试，并非完整意义上的原生 32 fps 训练与生成。部分 33B 结果依赖 B300 多 GPU、序列并行和独立解码 GPU，不能直接等同于单 GPU 部署。论文未明确说明在更长时间跨度、动作空间显著扩大或输入分布发生变化时的稳定性。
