# WorldAttention: An Efficient Attention Architecture for Interactive Video World Models

- **日期**：2026-09-29
- **评分**：78/100
- **作者**：Zeyu Zhang, Jinyuan Mao, Dakai An et al.
- **方向**：World Models
- **论文**：[arXiv 2609.34606](http://arxiv.org/abs/2609.34606v1)
- **代码**：未开源

## Abstract 中文翻译

借助自回归扩散范式，文本条件交互式视频世界模型旨在根据文本指令模拟具有时间一致性的环境。尽管实现低延迟、长时长生成对于具身智能和基于仿真的规划至关重要，现有框架主要依赖滑动窗口机制来限制计算复杂度。然而，这种方法必然会牺牲历史上下文，从而削弱长程交互能力。相反，维护完整历史缓存在计算和内存方面仍然难以承受：注意力的二次复杂度会带来过高的计算开销，而 KV 缓存的线性增长则不可避免地导致 GPU 内存耗尽。为克服这些局限，我们提出 WorldAttention，一种面向系统设计的注意力架构，通过专用注意力内核与分层 KV 缓存管理的协同设计实现高效率。首先，我们引入混合稀疏注意力（HSA），将线性全局注意力与头部自适应稀疏注意力相结合。此外，我们设计了分层 KV 缓存（HKV），将历史 KV 对组织为跨多级存储、按语义建立索引的页面，从而实现细粒度检索并控制 GPU 中的数据驻留。这两项设计由定制内核提供支持，可将理论效率有效转化为实际性能。在 VBench-Long 和 InterVBench 上的大量实验表明，WorldAttention 持续超越此前的先进方法，在两个基准上分别取得 0.9472 和 0.9668 的主体一致性得分。

## 全文总结

论文面向文本条件的交互式长视频世界模型，解决完整历史上下文带来的注意力计算和 KV 缓存内存开销问题。方法由分层 KV 缓存（HKV）和混合稀疏注意力（HSA）组成：HKV 将历史缓存分页并跨 GPU、CPU 和 NVMe 分层管理，通过提示级和页面级检索选择相关视觉记忆；HSA 以线性全局注意力建模长程依赖，并以头部自适应的块稀疏注意力保留局部细节。配合针对内存布局优化的定制内核，系统在 VBench-Long 和 InterVBench 上获得较高的一致性、质量和提示跟随效果，并在单张 H100 上达到 22 FPS，端到端实现 2.21 倍加速。

## 核心贡献

1. 提出专为交互式长视频生成设计的 WorldAttention 架构，以缓解二次注意力计算和持续增长的 KV 缓存带来的效率与内存瓶颈。 2. 提出分层 KV 缓存（HKV），将历史 KV 划分为语义页面，并在 GPU、CPU 和 NVMe 多级存储间进行细粒度检索、迁移和驻留管理。 3. 提出混合稀疏注意力（HSA），结合线性全局注意力、动态块稀疏注意力和头部级自适应稀疏率，在全局上下文覆盖与局部细节建模之间取得平衡。 4. 设计与缓存组织和稀疏模式匹配的定制注意力内核，优化非连续内存访问和执行并行度；相较 FlashAttention-3，稀疏内核最高加速 14.02 倍，结合 HKV 的端到端加速为 2.21 倍。 5. 在 VBench-Long 和 InterVBench 上验证方法在长时段交互视频中的主体一致性、背景一致性、运动平滑性、提示对齐和推理吞吐优势。

## 与课题的关系

与研究重点高度相关。论文直接研究自回归扩散式、文本条件交互视频世界模型，强调跨数十秒至分钟级生成时保持历史记忆、主体身份、场景一致性和因果连贯性。HKV 支持全历史上下文的分层存储与语义检索，适用于长视频、交互式和闭环式环境模拟；HSA、块稀疏注意力和线性注意力降低长序列计算成本；KV 缓存复用、专用内核和多级内存管理对应缓存重用、稀疏注意力与实时生成方向。论文报告单张 NVIDIA H100 上 22 FPS，并在 60 秒及更长时长设置中验证效率，但其重点是文本驱动的交互生成，而非明确的动作条件控制或机器人闭环策略学习。

## 局限 / 待核实

论文明确显示，当前检索主要采用提示级 Top-1 候选块，再从其中选择页面；对于涉及多个事件的提示，扩大候选块数量会分散固定页面预算并引入无关上下文，因此该设计对多事件场景可能存在局限。面对语义相似的历史片段，实验显示性能会小幅下降。稀疏块注意力内核本身仅占 HSA 总延迟的 1.86%，KV 重组和连续内存复制仍是主要开销，说明单独优化注意力内核不能完全解决端到端效率问题。实验主要基于 Wan2.1-T2V、480p 视频以及 VBench-Long 和 InterVBench；论文未明确说明在更广泛模型、分辨率、场景分布或真实具身闭环任务中的泛化能力。训练过程使用 32 张 H100、192 个 CPU 核心和 960 GB CPU 内存，资源需求较高。
