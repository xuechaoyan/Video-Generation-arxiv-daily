# ShowNow: Fine-Grained Speculative Streaming for Responsive World Models

- **日期**：2026-11-27
- **评分**：76/100
- **作者**：Yiren Song, Guian Fang, Mike Zheng Shou
- **方向**：World Models
- **论文**：[arXiv 2611.34693](http://arxiv.org/abs/2611.34693v1)
- **代码**：未开源

## Abstract 中文翻译

交互式世界模型必须在持续生成视频的同时，及时响应用户操作。仅有实时吞吐率并不能解决输入延迟：粗粒度生成会延迟动作更新，而在输入到达后才开始生成又会增加响应路径上的工作量。我们提出 ShowNow，一种细粒度推测式流式框架，利用播放期间可用的计算资源，在输入到达前准备动作条件化的未来。单潜变量提交支持高频决策，可配置的准备机制覆盖一到八个动作。我们构建了匹配的多未来数据集，用于从共同状态训练不同的后续轨迹；共享历史的树执行和融合提交机制提高了准备效率。在单张 H100 上，我们的 5B 模型在准备八个未来的情况下，能够以 16 fps 持续生成 480p 视频。在 ViZDoom 中，与原生阻塞式 SolarWM-FT 部署相比，完整的 ShowNow 部署将输入到显示的中位延迟从 620 毫秒降低至 208 毫秒。匹配策略实验将重启空帧比例从 1.56% 降低至 0.09%（降低 94%），并改善了对动作变化的按时响应。这些结果表明，细粒度提交与提前准备具有互补作用，同时也存在已测量的视觉保真度和长时一致性权衡。ShowNow 将播放期间的计算转化为响应迅速的视觉交互。

## 全文总结

论文提出 ShowNow，用于降低交互式世界模型的视频输入响应延迟。系统以单潜变量进行更频繁的提交，并在播放期间从同一历史状态并行准备多个动作条件化未来；用户输入到达后直接选择匹配分支，再将其作为下一轮生成的共同历史。作者构建了匹配的八动作多未来 ViZDoom 数据集，并结合因果蒸馏、自强制训练、分支树注意力、共享历史缓存和融合提交实现实时推理。在单张 H100 上，5B 模型可在 480p、16 fps 下准备八个未来；完整部署将中位输入到显示延迟从 620 ms 降至 208 ms，并显著减少重启空帧。实验还显示，提前准备可提高临近显示截止时间时的按时响应和播放连续性，但细粒度自回归及部署优化会带来视觉质量和长时一致性下降。

## 核心贡献

1. 提出 ShowNow 细粒度推测式流式框架，将播放期间的计算用于提前准备动作条件化未来，并统一单未来和多未来准备，在计算开销与响应速度之间提供可配置权衡。 2. 构建并发布从相同世界状态分叉的匹配多未来数据集，包含八种动作、持续动作和动作切换，用于训练不同动作下的一致历史与差异化后续。 3. 提出共享历史的分支树注意力、历史缓存、分区注意力和融合提交机制，避免重复计算并降低多分支推理的时间和显存开销。 4. 结合教师适配、AnyFlow 因果蒸馏和 Self-Forcing，训练三步去噪、单潜变量更新的实时生成模型。 5. 在单张 H100 上实现 5B 模型以 480p、16 fps 准备八个未来，并通过实验证明其在输入到显示延迟、空帧比例、截止时间内响应和高分辨率 33B 扩展方面的效果。

## 与课题的关系

论文与研究重点高度相关。它直接研究动作条件化视觉世界模型的闭环交互，将用户动作作为条件，并通过 prepare–select–commit 循环持续生成和更新视频。其单潜变量提交、因果自回归生成和播放期间提前推测未来，分别对应细粒度决策、流式/长视频生成和降低输入响应延迟。共享历史树执行、滚动缓存、分区注意力与融合提交直接涉及稀疏或复用历史计算、缓存复用和实时推理优化。AnyFlow 蒸馏与三步采样则对应生成加速和蒸馏。实验还量化了 16 fps 实时生成、32 fps 加速播放、动作切换响应以及输入到显示延迟，体现了面向闭环模拟的实际交互性能。

## 局限 / 待核实

论文报告了若干局限和权衡：ShowNow 的细粒度自回归生成相较于基线具有更低的短期动作切换延迟，但其整体动作准确率和稳定后的准确率并不全面占优，视觉指标也出现下降；长时一刻钟级滚动中，部署路径和更长的自回归历史会降低生成质量与一致性。多未来准备需要显著的 GPU 计算资源，八未来配置占用约 80% GPU 忙碌时间，并依赖单张 H100 才能达到报告的实时点。覆盖动作之外的输入仍需重新生成，无法直接享受预准备分支的收益。实验主要基于 ViZDoom 和有限的动作集合，跨环境、跨任务及真实机器人闭环控制的泛化能力未被充分验证。33B 结果使用八路序列并行、B300 GPU 和额外 GPU 解码的建模设置，不等同于单 GPU 实时部署。论文未明确说明更复杂动作空间、长期用户策略变化和极端负载下的性能上限。
