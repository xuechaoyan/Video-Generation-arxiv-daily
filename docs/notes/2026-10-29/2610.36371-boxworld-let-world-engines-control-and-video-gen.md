# BoxWorld: Let World Engines Control and Video Generators Render

- **日期**：2026-10-29
- **评分**：78/100
- **作者**：Zike Wu, Ahmed Hatem, Chintan Trivedi et al.
- **方向**：World Models
- **论文**：[arXiv 2610.36371](http://arxiv.org/abs/2610.36371v1)
- **代码**：未开源

## Abstract 中文翻译

我们致力于解决构建具有用户自定义行为的实时交互式视频世界这一挑战。这类世界必须跟踪物体状态、应用交互规则，并在用户行动时渲染由此产生的结果。然而，现有端到端视频世界模型通常将交互动力学学习在生成器内部，因此难以指定物体级规则并推理其后果。本文提出 BoxWorld，将交互推理与生成式渲染分离。给定用户指定的规则，一个编码代理会创建 Box World Engine，由其确定交互结果，并通过由布局框、持久物体属性和动态状态变量组成的轻量级接口公开更新后的物体状态；外观和物理效果则交由生成式渲染完成。随后，Box-State Generative Renderer 以自回归方式将不断演化的状态流渲染为视频，从而实现对物体运动、状态切换和条件事件的在线控制。渲染这一状态流并非易事：渲染器必须实时响应物体级状态更新，同时与已生成的历史保持连贯。为此，我们提出三阶段训练策略：从开放领域视频中学习物体定位，从游戏视频中学习状态转移（两者的标注均由自动方式生成），最后在模型自行生成的历史上进行 rollout 蒸馏。我们还提出 PairedStateBench，这是一个用于细粒度交互控制的成对基准。BoxWorld 大幅优于端到端世界模型，并在多个公开基准上保持竞争力。项目主页：https://boxworld-web.github.io。

## 全文总结

BoxWorld 将交互逻辑与视频渲染解耦：编码代理依据用户规则生成 Box World Engine，显式维护物体的位置、身份外观和动态状态；实时自回归渲染器则根据这些状态流生成视觉结果。该方法通过掩码布局定位、游戏状态动力学适配和自生成历史上的 rollout 蒸馏进行训练，并利用自动视频结构标注避免依赖动作配对交互日志。实验表明，BoxWorld 在条件事件触发、禁止事件抑制、多阶段任务和布局到视频生成方面显著优于端到端基线，同时以约 20.7 FPS 实时运行，并保持接近骨干模型的视频质量。

## 核心贡献

1. 提出 BoxWorld 框架，将由编码代理创建的 Box World Engine 用于显式执行用户定义的交互规则，将 Box-State Generative Renderer 用于根据对象级状态生成视频。 2. 提出 Object-Centric State Interface，以布局框、持久物体属性和动态状态变量作为轻量级控制表示，并设计逐帧掩码交叉注意力，使视觉区域关注其对应物体。 3. 提出三阶段训练策略：在开放领域视频上进行 Masked Layout Grounding，在游戏视频上进行 State Dynamics Adaptation，并通过 Rollout Distillation 适配模型自身生成的历史、恢复少步实时生成能力。 4. 使用现成感知模型从视频自动提取状态标注，不需要动作配对的交互日志。 5. 提出 PairedStateBench，用成对分支评估条件事件是否正确触发、非指定后果是否被抑制以及多阶段任务是否完成。

## 与课题的关系

本文与研究重点高度相关。它面向实时视频生成和视频扩散式生成，使用少步、因果、自回归渲染器进行异步流式生成，报告约 20.7 FPS。它直接研究动作条件的视觉世界模型和闭环交互模拟：用户动作由 Box World Engine 根据显式规则处理，更新后的对象状态再驱动视频生成，形成“动作—状态更新—渲染—后续动作”的闭环。其 Object-Centric State Interface 提供了比隐式端到端模型更细粒度的对象控制，同时避免完整物理模拟器的高成本。三阶段训练中的 rollout 蒸馏用于缓解自回归生成中的分布偏移，并改善长时域生成；LoRA 适配器最终合并入骨干网络，不增加推理运行时成本。

## 局限 / 待核实

论文明确指出，BoxWorld 的渲染器仍需处理状态更新导致的历史部分失效问题，并且只能通过粗粒度布局框和状态变量间接生成具体的外观与物理效果；相比提供更细空间支持的表示，布局框的空间精度有限。方法依赖现成感知模型自动提取目标框、跟踪、属性和状态描述，这些标注可能带来感知误差，论文未系统量化其影响。Box World Engine 的规则由编码代理生成，论文未充分讨论代码生成错误、规则复杂度扩展性或安全性。训练状态动力学主要使用约 4,000 段短游戏视频，真实物理世界和更广泛交互类型的泛化能力尚不明确。论文未明确说明长时间运行时的状态缓冲增长、错误累积、用户规则冲突处理以及生成质量和交互延迟之间的完整权衡。
