# BoxWorld: Let World Engines Control and Video Generators Render

- **日期**：2026-10-29
- **评分**：78/100
- **作者**：Zike Wu, Ahmed Hatem, Chintan Trivedi et al.
- **方向**：World Models
- **论文**：[arXiv 2610.36371](http://arxiv.org/abs/2610.36371v1)
- **代码**：未开源

## Abstract 中文翻译

我们致力于解决构建具有用户定义行为的实时交互式视频世界这一挑战。这类世界必须跟踪物体状态、应用交互规则，并在用户行动时渲染由此产生的后果。然而，现有端到端视频世界模型通常在生成器内部学习交互动力学，因此难以指定对象级规则并推理其后果。本文提出 BoxWorld，将交互推理与生成式渲染分离。给定用户指定的规则，编码代理会创建一个 Box World Engine，用于确定交互结果，并通过由布局框、持久对象属性和动态状态变量组成的轻量级接口公开更新后的对象状态，将外观和物理效果留给生成式渲染。随后，Box-State Generative Renderer 以自回归方式将不断演化的状态流渲染为视频，从而实现对物体运动、状态切换和条件事件的在线控制。渲染这一状态流并非易事：渲染器必须实时响应对象级状态更新，同时与已生成的历史保持连贯。为此，我们提出三阶段训练策略：首先从开放域视频中学习对象定位与状态关联，再从游戏视频中学习状态转移，两者的标注均由自动方法生成，最后在模型自行生成的历史上进行 rollout 蒸馏。我们还提出 PairedStateBench，一个用于细粒度交互控制的成对基准。BoxWorld 大幅超越端到端世界模型，并在多个公开基准上保持竞争力。项目主页：https://boxworld-web.github.io。

## 全文总结

BoxWorld 面向具有用户定义行为的实时交互式视频世界，将“世界如何交互”与“画面如何呈现”分离。编码代理根据规则生成 Box World Engine，显式维护对象的布局框、持久属性和动态状态，并异步向视频渲染器提供状态流；基于 LongLive 初始化的 Box-State Generative Renderer 则以自回归、少步数方式生成视频。作者通过掩码布局定位、游戏状态动力学适配和 rollout 蒸馏三个阶段训练渲染器，并利用现成视觉模型从视频自动提取状态标注。实验显示，该方法在 PairedStateBench 上显著提升条件事件触发、禁止事件抑制和多阶段任务完成能力，同时以约 20.7 FPS 运行，在视频质量、长视频生成和布局到视频任务上保持较强表现。

## 核心贡献

1. 提出 BoxWorld 框架，通过 Box World Engine 显式执行用户规则，通过 Box-State Generative Renderer 负责视觉渲染，并以包含布局框、持久属性和动态状态的 Object-Centric State Interface 连接两者。2. 提出三阶段训练策略：在开放域视频上进行 Masked Layout Grounding，在游戏视频上进行 State Dynamics Adaptation，并通过模型自身 rollout 的蒸馏恢复少步数、自回归生成能力。3. 设计从开放域和游戏视频自动提取对象状态与状态转移的标注流程，无需动作配对的交互日志或预定义模拟器。4. 提出 PairedStateBench，用成对分支评估细粒度交互控制，包括条件事件触发、非指定后果抑制、状态时序一致性和多阶段任务完成。5. 实验证明 BoxWorld 在细粒度交互控制上明显优于端到端世界模型，并在公开视频质量、长时域和布局到视频基准上保持竞争力，同时实现实时渲染。

## 与课题的关系

与研究重点高度相关。该工作直接研究视频生成、视频世界模型和闭环交互模拟：世界引擎根据用户动作和规则更新状态，生成器根据最新状态反馈连续渲染，从而形成异步的引擎—渲染器闭环。它采用自回归、因果、流式生成，状态更新可在下一批生成帧中在线生效；使用 rollout distillation 将生成过程恢复为四步去噪，并以约 20.7 FPS 实时运行。按对象状态进行掩码交叉注意力，减少无关状态干扰；布局框、对象属性和动态状态构成轻量显式接口，在控制精度与跨场景泛化之间取得平衡。该方法尤其适合研究动作条件视觉世界模型、可编程交互规则、长时域一致性、实时生成和基于自身历史的分布适配。

## 局限 / 待核实

论文明确显示该方法仍依赖生成式渲染器来补全纹理、光照、风格以及烟雾、溅水等物理效果，因此 Box World Engine 的符号规则并不等同于完整的物理模拟，复杂物理一致性可能受限。状态接口主要由二维布局框、持久属性和动态状态组成，相比更密集的 blob、3D 缓存或完整模拟器，空间表达能力较粗；在 YouTube-VIS 上其 mIOU 为 0.572，低于使用更细空间表示的 BlobGEN-Vid。训练状态来自 Grounding DINO、SAM 2、视频描述和对象级标注等现成感知模型，自动标注误差可能影响对象跟踪、属性和状态转移学习。训练状态动力学使用约 4,000 个短游戏视频，覆盖范围可能限制对现实世界复杂交互的泛化。论文还指出状态更新会使部分生成历史过时，渲染器必须自行判断哪些内容保留、哪些内容改变；尽管 rollout 蒸馏有所缓解，长时域自回归生成仍存在累积误差风险。除上述问题外，论文未明确说明更广泛现实场景中的具体失效边界。
