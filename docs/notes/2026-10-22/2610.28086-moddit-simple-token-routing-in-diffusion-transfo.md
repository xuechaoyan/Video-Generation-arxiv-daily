# MoDDiT: Simple Token Routing in Diffusion Transformers

- **日期**：2026-10-22
- **评分**：76/100
- **作者**：Jarek Liesen, Matthew T. Jackson, Benjamin Ellis et al.
- **方向**：Video Generation, World Models, Efficient Video Diffusion
- **论文**：[arXiv 2610.28086](http://arxiv.org/abs/2610.28086v1)
- **代码**：未开源

## Abstract 中文翻译

实时视频生成、交互式世界模型和端侧图像合成几乎已经成为现实。扩散 Transformer（DiT）能够实现出色的样本质量，使瓶颈转移到了模型本身的吞吐量上。自然图像本质上具有稀疏性，因为图像的大部分区域通常是背景，对场景内容贡献很小，也容易去噪。DiT 未能利用这种稀疏性，因为它以静态且统一的方式处理图像 token。我们提出 MoDDiT，这是一种简单的架构修改方法，能够学习将 token 路由至 MLP 和自注意力操作。通过分别将 token 路由经过这两个模块，MoDDiT 可以在 MLP 中动态分配计算量，并且这种分配会随 token、图像和去噪时间步而变化。使用 MoDDiT 从头训练图像生成模型，可以显著降低训练和推理成本，处理的 token 数量最低可达到原来的 12.5%。通过提高稀疏性和模型深度，MoDDiT 在降低成本的同时，相比不进行路由的基线模型提升了生成性能。学习得到的计算分配具有可解释性，揭示了计算量如何随视觉内容和噪声水平变化。我们还使用 MoDDiT 训练视频生成模型，发现计算分配与运动相关；并将一个稠密的双向视频模型蒸馏为稀疏的自回归学生模型。

## 全文总结

论文提出 MoDDiT，通过轻量级路由器分别决定 token 是否经过自注意力和 MLP，从而根据内容、样本和去噪阶段动态分配计算。在 ImageNet 上，MoDDiT 在相近或更低 FLOPs 下取得优于或接近 DiT 的图像生成效果，最低可处理 12.5% 的 token。在 1X 机器人第一视角动作条件视频预测中，12.5% 容量的 ST-MoDDiT 使用更少去噪 FLOPs，同时提升多个预测时刻的 PSNR，且路由比例与视频运动强度正相关。论文还将 Wan2.1 蒸馏为稀疏的少步自回归视频生成器，在 VBench 总分仅下降 5.35% 的情况下减少约 23.98% 的 Transformer FLOPs。

## 核心贡献

1. 提出 MoDDiT，一种无需辅助路由损失、支持并行 GPU 训练且能同时降低训练和推理 FLOPs 的 token 路由机制。\n2. 对自注意力采用固定容量路由，对 MLP 采用跨 batch 的动态容量分配，使计算量能够随 token、图像内容和去噪时间步变化。\n3. 在 ImageNet 图像生成、1X 动作条件视频预测和 Wan2.1 稀疏蒸馏三个场景中进行验证，展示了质量—计算量权衡的改善。\n4. 分析路由行为的可解释性，发现计算分配偏向低噪声阶段、高潜变量方差区域以及视频中运动变化更大的区域。\n5. 将稠密双向视频扩散模型转化为稀疏、少步、自回归学生模型，证明 token 路由可以与视频蒸馏和闭环式长程生成技术结合。

## 与课题的关系

论文与研究重点高度相关。它直接面向视频扩散和实时生成，通过 token 级稀疏路由减少每个去噪步骤的计算，适合降低实时视频生成和交互式世界模型的延迟。在 1X 世界模型数据集上，模型以历史视频帧和机器人连续动作作为条件，自回归预测后续潜在视频帧，属于动作条件视觉世界建模；路由还会根据时空变化将更多计算分配给动态区域。其 Wan2.1 实验进一步结合少步蒸馏、稀疏注意力和自回归视频生成，说明该方法可用于流式或长视频生成的计算压缩。方法本身不依赖缓存复用，但其对静态区域少分配计算的机制与跨帧复用、稀疏注意力和实时推理优化具有互补性。

## 局限 / 待核实

论文明确指出，实验受计算资源限制，尚未覆盖更多数据集、架构和生成算法，因此需要在 ArtBench、Food、Taichi-HD、Minecraft VPT 等数据集上进一步验证。FLOPs 的下降不一定转化为实际墙钟时间的下降：小 batch 或少量并行样本生成时，gather/scatter 开销以及高度优化的稠密矩阵乘法可能抵消收益；论文仅在 batch size 32 时报告了吞吐提升。稀疏蒸馏模型在空间关系和多对象生成方面较弱，且 VBench 总分比稠密基线低 5.35%。方法引入了 MLP 和自注意力的容量超参数，目前两者使用相同容量，但论文观察到它们具有不同的分配动态，最佳容量设置尚未确定。论文未明确说明在更长时间范围内的闭环稳定性、动作控制误差累积、端到端实时延迟以及缓存复用方面的表现。
