# FastFrames: Video Generation at Interactive Latency

- **日期**：2026-11-18
- **评分**：79/100
- **作者**：Gene Chou, Guandao Yang, Fujun Luan et al.
- **方向**：Video Generation, Autoregressive and Streaming Video
- **论文**：[arXiv 2611.23226](http://arxiv.org/abs/2611.23226v1)
- **代码**：未开源

## Abstract 中文翻译

自回归视频扩散模型根据新的观测和输入生成视频帧，因此有望成为交互式视觉体验的媒介。然而，现有模型的速度通常比流畅交互所需的速度慢几个数量级。本文提出 FastFrames，一系列无需牺牲质量即可实现交互式延迟的快速自回归视频扩散模型。我们对当前最先进模型的推理流程进行了分析，发现一些通常被视为固定实现细节的操作（例如 VAE 解码和 KV 缓存更新）实际上占据了端到端推理延迟的一半以上。我们质疑这些组件不可或缺的假设，并用轻量级替代方案取代它们。我们的 1.3B 变体在单个 B200 GPU 上每帧运行时间为 36 毫秒，即每秒 28 次响应（RPS），同时保持了与某个最先进模型相当的生成质量，而后者的速度几乎慢 8 倍。我们的 14B 变体在由 8 个 B200 GPU 组成的节点上每帧运行时间为 45 毫秒，即每秒 22 次响应，并且具有显著更好的视觉质量和真实感。我们展示了 FastFrames 如何在相机条件和物理条件视频生成等应用中实现实时交互。

## 全文总结

本文针对自回归视频扩散模型端到端响应延迟过高的问题，提出 FastFrames。作者通过延迟剖析发现，VAE 像素解码和 KV 缓存更新等非去噪环节是主要瓶颈，而不仅仅是扩散采样步骤。为此，FastFrames 使用基于 ConvNeXt 的轻量级像素解码器替代 VAE，使用轻量级网络修复 KV 缓存，并结合持久化缓存、条件预计算、分段注意力、算子融合、CUDA Graph 和上下文并行等系统优化。在 480p、B200 GPU 上，1.3B 模型达到 36 毫秒/帧和 27.8 RPS，14B 模型在 8 个 GPU 上达到 45 毫秒/帧和 22.2 RPS，同时保持或提升相对于基线的 VBench 质量。优化也被迁移到相机条件和物理条件模型，使其响应延迟降至约 51–52 毫秒。

## 核心贡献

提出 FastFrames，一套面向交互式延迟的自回归视频扩散模型与推理方案；通过轻量级 ConvNeXt 像素解码器替代高成本 VAE 解码，在保持视觉质量的同时将解码延迟从 147 毫秒降至约 1 毫秒；设计 KV 缓存修复网络，以轻量计算替代额外的 DiT 缓存更新，将缓存更新延迟大幅降低；提出面向端到端逐帧关键路径的系统优化，包括持久化 KV 缓存、条件预计算、融合 QKV 投影、分段注意力和 CUDA Graph；利用上下文并行实现多 GPU 加速；在 1.3B 和 14B 模型上验证了交互式延迟与有竞争力的视觉质量，并将方法应用于相机条件和物理条件视频生成。

## 与课题的关系

论文与研究重点高度相关。它直接研究自回归、因果和流式视频生成，并将交互式生成的核心指标定义为输入到首个受影响 RGB 帧呈现之间的逐帧延迟，而非仅报告可摊销的 FPS。其主要技术聚焦于实时生成、少步扩散、KV 缓存复用与高效更新、注意力分段、上下文并行和系统级硬件优化。相机条件与物理条件实验表明，这些优化可支持动作或外部控制驱动的闭环视觉交互，因此也与动作条件视觉世界模型和实时模拟相关。论文还指出，长期一致性、物理合理性、更高分辨率以及在轻量硬件上的部署仍是后续方向。

## 局限 / 待核实

评估主要集中于 480p 文本到视频生成，并依赖高端 B200 GPU；14B 模型达到交互式延迟需要 8 个 GPU。论文明确指出，像素解码器必须针对每个模型单独微调，不能像 Wan VAE 那样在同系列模型间共享。带有额外动作条件的模型仍比基础文本到视频模型更慢，例如 LingBot 14B 在 8 个 GPU 上为 233 毫秒。作者还指出，当前方法尚未解决长期一致性和物理合理性问题，也未充分覆盖更高分辨率或更轻量硬件。
