# FastFrames: Video Generation at Interactive Latency

- **日期**：2026-11-18
- **评分**：79/100
- **作者**：Gene Chou, Guandao Yang, Fujun Luan et al.
- **方向**：Video Generation, Autoregressive and Streaming Video
- **论文**：[arXiv 2611.23226](http://arxiv.org/abs/2611.23226v1)
- **代码**：未开源

## Abstract 中文翻译

自回归视频扩散模型根据新的观测和输入生成帧，因此有望成为交互式视觉体验的理想媒介。然而，现有模型的速度通常比流畅交互所需的速度慢几个数量级。本文提出 FastFrames，一系列无需牺牲质量即可实现交互延迟的快速自回归视频扩散模型。我们对当前最先进模型的推理流程进行了分析，发现通常被视为固定实现细节的操作（例如 VAE 解码和 KV 缓存更新）实际上占据了端到端推理延迟的一半以上。我们质疑这些组件是否不可或缺，并以轻量级替代方案取代它们。我们的 1.3B 版本在单个 B200 GPU 上每帧运行时间为 36 毫秒，即每秒 28 次响应（RPS），同时保持了与一个速度几乎慢 8 倍的先进模型相当的生成质量。我们的 14B 版本在由 8 个 B200 GPU 组成的节点上每帧运行时间为 45 毫秒，即 22 RPS，并呈现出显著更好的视觉质量和真实感。我们展示了 FastFrames 如何支持相机条件和物理条件视频生成等应用中的实时交互。

## 全文总结

本文针对自回归视频扩散模型端到端响应速度过慢的问题，提出 FastFrames。作者通过延迟剖析发现，VAE 解码和 KV 缓存更新等非去噪操作是主要瓶颈，因此分别使用轻量级 ConvNeXt 像素解码器和 KV 修复网络替代原组件，并结合持久化缓存、分段注意力、算子融合、CUDA Graph 及上下文并行等系统优化。在 480p 条件下，1.3B 模型单 GPU 达到 36 毫秒/帧，14B 模型 8 GPU 达到 45 毫秒/帧，同时保持与基线相当或更好的 VBench 质量。优化也被迁移到相机条件和物理条件模型，使其响应延迟接近交互目标。

## 核心贡献

1. 提出以端到端每帧延迟和每秒响应数衡量交互式视频生成性能，并将 50 毫秒（20 RPS）作为目标。 2. 设计轻量级 ConvNeXt 像素解码器，将 VAE 解码延迟从 147 毫秒降至约 1 毫秒，同时保持视觉细节和质量。 3. 提出 KV 修复网络，以轻量网络预测干净潜变量对应的缓存修正，将 KV 更新开销大幅降低。 4. 结合持久化 KV 缓存、预计算条件、融合 QKV 投影、分段注意力、CUDA Graph 和多 GPU 上下文并行，降低 DiT 推理延迟。 5. 构建 1.3B 和 14B 的 FastFrames 模型，在交互延迟范围内达到具有竞争力的生成质量，并验证其对相机条件和物理条件视频模型的加速效果。

## 与课题的关系

论文与研究重点高度相关。它直接研究自回归、因果、流式视频生成的实时推理，针对每个新输入到首个受影响 RGB 帧呈现之间的延迟进行优化。其方法涉及视频扩散加速、少步蒸馏模型的端到端优化、KV 缓存复用与快速更新、稀疏/分段注意力、硬件感知并行以及高效像素解码。通过相机条件和物理条件生成实验，论文还与动作或控制条件视觉世界模型及闭环交互仿真相关；不过其主要定量评测仍集中在文本到视频生成，而不是完整的闭环世界模型任务。

## 局限 / 待核实

论文明确指出，评测主要集中于 480p 文本到视频生成，并依赖高端 B200 GPU；未来仍需支持更高分辨率和更轻量的硬件形态。作者还指出，加入动作条件而不增加延迟、改善长期一致性和物理合理性是尚未解决的问题。相机条件和物理条件模型经过优化后仍比文本到视频模型更慢，部分原因是需要更多扩散步、每个自回归步骤预测多个潜在帧，并处理额外条件。与可跨同系列模型共享的通用 VAE 不同，像素解码器需要针对每个模型分别微调。论文未明确说明更长视频时长、复杂闭环控制场景和广泛硬件平台上的性能。
